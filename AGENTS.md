# Water Sort Puzzle

A level-based colour-sorting puzzle: pour layers of coloured water between bottles until every
bottle holds one colour. 100 levels in 10 chapters, each chapter adding one twist, plus daily, weekly
and endless boards. Target platforms: web, iOS and Android from one codebase.

Status: playable web build with all mechanics, modes and progression; tested. Native builds have never been made.

## Stack

- TypeScript, PixiJS 8 (canvas rendering), Vite (dev server and web build)
- Capacitor 8 for store packaging (config only so far; `ios/` and `android/` do not exist yet)
- No UI framework. HUD, buttons and overlays are plain DOM in `src/body.html` + `src/style.css`
- Sound is synthesized with Web Audio in `src/audio.ts`; there are no audio files

## Layout

- `src/core/game.ts` — rules: pour, win, stuck. Pure functions, no DOM, no Pixi. Every function takes a `Rules`
  object (capacity per bottle, labels, locks, whole-run pouring); `DEFAULT_RULES` is four layers and nothing else.
  `WILD` (-1) is a layer that matches any colour.
- `src/core/chapters.ts` — the ten chapters: twist, colour range, theme (CSS colours, vessel, liquid), tutorial tip.
- `src/core/solver.ts` — weighted A* over the rules. Verifies levels at build time and powers the Hint button at run time.
- `src/core/generator.ts` — `buildBoard` applies modifiers, `rateBoard` rates difficulty, `makePuzzle` generates at run time.
- `src/core/modes.ts` — daily, weekly and endless boards seeded from the calendar (`dayKey`, `weekKey`).
- `src/core/achievements.ts` — achievement list and `starsFor`.
- `src/core/levels.json` — generated by `scripts/gen-levels.ts`. Never edit by hand.
- `src/view/bottle.ts` — one bottle: geometry from `makeGeom(capacity, vessel)`, glass, liquid, cork, label tag, padlock.
  Liquid surface stays level while the bottle tilts. `HIDDEN` (-2) is the view-only id for a fogged layer.
- `src/view/board.ts` — layout, selection, the pour animation, unlock animation, hints.
- `src/view/fx.ts`, `src/view/tween.ts` — particles, star field, promise-based tweens.
- `src/main.ts` — game controller: modes, state, undo history, fog tracking, HUD, menu (modes, chapters, achievements), win flow.
- `src/storage.ts` — save/load in `localStorage`, migration from the v1 key.
- `src/entry.ts` — Vite entry: imports the CSS, then `main.ts`; registers the service worker in production builds.
- `public/` — static files copied into the build: bundled fonts (`fonts/fonts.css`), PWA icons, `manifest.webmanifest`.
- `scripts/pwa.mjs` — runs after `vite build` and writes `dist/sw.js`, a service worker that precaches the whole build.
- `.github/workflows/pages.yml` — tests, builds and deploys `dist/` to GitHub Pages on every push to `main`.

## Rules as implemented

- A bottle holds `capacity` layers (4 by default, 5 in "tall", 3–5 per bottle in "mixed"). Pour into an empty bottle or onto a matching colour.
- A pour moves as many layers of the top colour run as fit (partial pours are allowed, except under `wholeRun`).
- Wild layers join whichever run they sit in; the run colour is the first real colour from the top.
- A labelled bottle accepts only its colour. A locked bottle cannot be touched until the colour on its padlock is complete somewhere.
- Solved when every bottle is empty or full with one colour.
- Fog (`hidden`) and the move limit (`moveLimit`) live outside the rules: the view hides layers the player has not seen, the controller ends the attempt when the limit is hit.
- Levels: 1 is a fixed tutorial; 2–100 are generated per chapter (see `chapters.ts`). Every 5th level from 15 is "hard": one spare bottle instead of two (the locks chapter keeps two spares and adds a colour).
- Difficulty = solution length × (1 + 2 × share of no-lookahead playouts that get stuck). Within a group, levels ascend by it.
- Stars: 3 at par or better, 2 within par + 3, 1 for finishing. Hints: 3 a day, +1 for the first three-star finish of a level, capped at 9.
- Daily and weekly boards are seeded from the local date / ISO week, so all players share them without a server. Endless raises colours with the streak and mixes in twists from streak 4.

## Things that must stay true

- `src/core/` imports nothing from the DOM or PixiJS. It has to run in Node for tests and level generation.
- Every shipped level is solved by the solver and the solution is replayed through the rules engine. `npm test` enforces this; do not weaken it.
- After any change to rules, solver or generator: run `npm run levels`, then `npm test`.
- Regenerating levels changes every board. Once the game is in a store, level content must not change for existing players; treat `levels.json` as frozen from then on and only append.
- Keep `import 'pixi.js/unsafe-eval'` at the top of `src/main.ts`. Without it PixiJS breaks under a strict Content-Security-Policy.
- The web build is a PWA: `index.html` carries the iOS home-screen meta tags and the manifest; fonts live in `public/fonts` (Google Fonts, OFL), nothing is fetched from a CDN. Cache matching in `sw.js` ignores `Vary`, otherwise assets served with `Vary: Origin` or `Vary: Accept-Encoding` miss the cache offline.
- `src/main.ts` must not import CSS (the single-file build bundles it with esbuild). CSS is imported in `src/entry.ts`.
- Overlays are shown and hidden with the `hidden` attribute. `style.css` has `[hidden] { display: none !important }`; removing it makes the level list cover the game.
- All text lives in the DOM, not on the canvas.
- Animations go through `tween()` so `prefers-reduced-motion` is respected.
- The save shape is `Save` in `src/storage.ts`, under the key `water-sort.save.v2`; `loadSave` still reads `v1`. Bump the key on incompatible changes and keep a migration.
- Generated boards (daily, weekly, endless) are stored in the save as full `Puzzle` objects, so a half-played board survives a reload even if the generator changes.
- `window.__waterSort` is a small handle used by the end-to-end test (`hints(n)` lifts the hint ration for the test). Keep its methods when refactoring `main.ts`.
- Board animations must survive a board swap mid-flight: `tickTweens` drops a tween whose target was destroyed, and `Board.pour/seal/unlock` check `destroyed` after every await.
- In-game text, code and comments are in English.

## Before calling a change done

1. `npm test`
2. `npm run build`
3. For anything visual, run `npm run dev` and look at it at phone width (about 390×844) and on desktop.

## End-to-end test

`scripts/e2e.mjs` needs a Chromium binary and a static server:

1. `npm run build:single -- --local`
2. Serve `dist-single/` on port 4173
3. `CHROMIUM=<path to chrome or chromium> node scripts/e2e.mjs`

It is slow under software rendering (several minutes).

## Environment

- The owner develops on Windows. Run `npm install` in a Windows terminal; `node_modules` installed from Linux or WSL carries the wrong native binaries for Windows.
- iOS builds need macOS with Xcode. Android builds need Android Studio.
- `capacitor.config.ts` still has the placeholder `appId` `com.example.watersort`. It must be replaced before `cap add`, and cannot change after the first store release.
